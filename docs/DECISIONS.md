# Offline decision prototype

`go run ./cmd/rules -mode decision` demonstrates a fast recommendation checked by the native engine and applies it in an offline simulation. It does not operate the game client.

Construct `rules.DecisionInput` from a confirmed complete public `View`, a unique match identifier, phase `turn`, the active player, explicitly supplied candidate actions and a deadline made with `time.Now().Add(budget)`. Do not deserialize the deadline: it must retain Go's monotonic clock. The caller owns observation freshness, the candidate list and the final check against the current game state. `Fast` deterministically checks plays before passes and returns an error when the observation or candidates cannot be validated or the deadline has passed. It is a basic fallback, not an optimized game policy.

`Start` begins an asynchronous evaluation using a copy of the public view. `Poll` returns a completed proposal only for the same match, phase, full public state, candidate list and deadline, after another legality check. If no proposal is ready, use `Fast`; do not wait for analysis. `Close` cancels pending work. Starting again while cancellation is in progress returns an error and cancels the previous worker; retry later. One worker at most runs per service.

The slow policy compares immediate score changes and preserves cards when the opponent has passed and the round is already won. It is **one-move analysis**, not across-round search, opponent sampling, or a claim of playing strength. Opponent hand and deck identities are never provided to the policy; counts do not reveal their contents. Both paths use a public-state projection for legality, supported only for the six `native-v1` cards. The projection cannot establish observation authenticity, and native-v1 does not reproduce all client rules or Bearly Balanced behavior. The existing tracker requires a full-information initial state and is not a live partial-state estimator. Neither the prototype nor the demo provides the observed candidates or executes input.

On an Apple M4 Pro, `go test ./internal/rules -run '^$' -bench BenchmarkDecisionFast -benchmem -benchtime=1s` measured 507.6 ns/op, 744 B/op and 7 allocations/op for the small offline fixture. This excludes observation, candidate generation, client input, and scheduler delays; it is not a worst-case deadline guarantee.
